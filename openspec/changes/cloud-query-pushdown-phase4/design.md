# Execution design

Capability selection is deterministic and recomputed at execution. Same-connection PostgreSQL plans support scalar projections, filters, strict joins, grouping, count/sum/min/max, exact bounded arithmetic and ordering. Division and average retain application computation because PostgreSQL numeric division and BSON Decimal128 do not reproduce the application's 38-digit division. Unsupported types also retain the bounded fallback. Numeric pushdown checks every operand and intermediate against an exact decimal envelope, failing without partial totals outside it.

PostgreSQL checks and result statements share one read-only repeatable-read transaction. MongoDB single-collection aggregation uses snapshot read concern and simple collation, with missing values normalized to null and explicit runtime scalar checks. Cross-connection joins retain complete bounded application reads in this release; early aggregation is deferred until whole-source join validity and weighted aggregates have independent equivalence coverage.

Database execution remains synchronous: 45 seconds overall, 10 seconds per statement, at most one million source rows per dataset, four datasets, 500 output rows, 2 MB transferred and bounded cursor batches. The application fallback retains 5,000 rows per dataset. No query is queued past that window, so no background job or cancellation endpoint is introduced. Database failures return safe errors and no partial results. A physical explanation and execution duration, transferred rows/bytes and snapshot mode distinguish source rows checked from rows transferred.
