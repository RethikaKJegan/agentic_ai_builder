# Design

Extend the existing knowledge authoring package and import it only into isolated acceptance stores. New mappings/reference bindings and converters are snapshot-owned; old snapshots remain unchanged. Queries continue through BusinessRetrieval's bounded reader, native-type checks, owner authorization and source stamps. Candidate serial traversal is explicitly classified and cannot establish physical identity. Optional unavailable lookups are visible gaps and never trigger unrestricted queries.

A pure requirement registry defines stable facts, task scope, levels, providers, validators and recovery action identifiers. Evaluation emits structured gaps with context/provenance, preserving unknown/false and distinct source records. Retrieval returns these alongside legacy evidence. Investigation reports use scoped requirements as authoritative gaps, retaining nonmandatory agent suggestions separately. No LLM text can introduce a mandatory fact. Report completion and business-decision readiness remain separate.

Effectiveness is a read-only evidence-readiness capability using supported invoice/QA associations. Unsupported change/incorporation/population providers remain explicit; no operational scheduler, new agent, rate or causal inference is added. Synthetic events are accepted only by an explicit isolated scenario harness; live APIs do not accept fact overrides. Existing frontend-compatible fields are preserved.

Validate authoring/schema/compilation, native reference direction and ambiguity, dates, requirement levels, normalization and provenance, uncertainty, scenario isolation and Phase 1–3 regressions. Real-source checks use isolated application storage and bounded reads with no model calls; published code/data are not changed.
