# Phase 5 frontend-only controlled rollout

The user authorized Phase 5 implementation and loading the tested UI, as in prior phases. No backend source, API contracts, nginx, DNS, firewall, credential or database changes are required. The existing API and worker remain running; no worker drain, database restore, provider call or business mutation is part of this frontend-only rollout.

1. Pass frontend unit/type/lint, isolated production build and desktop/mobile/multi-tab browser tests; verify relevant backend security/lifecycle/concurrency regressions, actual isolated PostgreSQL, canonical contract/drift and strict OpenSpec. Record passing, failed-and-corrected and unexecuted results separately.
2. Preserve earliest Phase 5 existing-code originals and before/after hashes privately, retaining all Phase 1–4/user changes. Stage the exact browser-tested `.next` outside frontend and match BUILD_ID. Keep prior Phase 4 `.next` intact for rollback.
3. Stop only `agentic-builder-frontend.service`, move its `.next` to `.local/phase5-rollout/phase4-next`, atomically rename the tested artifact into `.next`, and restart frontend on loopback 3001. Keep API 8002 and worker PIDs unchanged. Existing live database contents and background automation continue normally.
4. Perform read-only live HTTPS/local authenticated reads, session/public-origin rejection, no-store/correlation checks, desktop/mobile editor modes and exact historical run inspection. Do not generate workflows, save/approve/publish/activate, run providers/workflows, edit settings or submit email/Sheets writes. Inspect screenshots and service health. Existing large overview can be slow; choose the bounded run collection for history selection.
5. If startup/smoke fails, stop only frontend, verify source checkpoint, restore only earliest Phase 5 existing frontend source and prior `.next`, then restart frontend. Keep API/worker/business databases/credentials unchanged; never restore an older database snapshot. Record failure and rollback before retrying.
