An opt-in service binds requests and internal tools to the authenticated workspace and literal project identity. Explicit table URLs/ranges/header mappings select arbitrary accessible sheets; mappings are reviewed setup, not fixed server IDs. A canonical workflow reads both sources and maps their actual outputs into a registered deterministic ingestion specialist. Incomplete fields are persisted and stop downstream preparation.

The coordinator persists a stable plan, workflow/run identities and phases in extension SQLite. It executes each exact workflow once with a durable retry key; pending gates, rejection and unknown outcomes stop advancement. A bounded worker polls only registered project runs and never decides approvals. Workflow review/publish uses current authorized operator identity; every external write retains a dedicated human runtime gate. No model is needed for tabular extraction, grouping or templated drafts. Registered internal tools remain available to the existing agent runtime under exact Registry grants.

Confirmed spreadsheet creation generates exact row-write targets. BOQ/vendor/RFQ projections are committed as sync intents with their record revisions, then routed through canonical gated upsert workflows. Confirmed runtime results acknowledge intents; rejected/failed/uncertain actions remain visible. Gmail draft IDs are stored as resource metadata and never treated as sent RFQs. Only this first slice is automated.
