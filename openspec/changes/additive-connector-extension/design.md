## Design
Compose existing WorkflowStore, RegistryService, RegistryAdapter and GraphRunner through a separate extension transport and launcher. Operator configuration creates an independent catalog and database; all provider credentials resolve only inside adapters. Existing tool schemas remain authoritative. New adapters implement reservation/invoke and use exact tool grants, resource allowlists, bounded HTTP transports and no automatic write retries. Reuse Sheets read/write adapters through restricted wrappers. Mail attachments use bounded private artifact references; no arbitrary filesystem path or bearer token enters tool outputs. Calendar writes use reviewed IDs and exact event bodies; Gmail sends use approved recipients and stable Message-IDs. External writes require Registry publication review and runtime action gates. Search uses Brave only when explicitly configured.

## Isolation
Default state is .local/connector-extension; refuse existing application database/token paths. The launcher never invokes create_configured_app or writes its fixed registry file. Provider setup uses a new OAuth token. Existing app startup stays unchanged. New sample workflows demonstrate connector plumbing only; no procurement decisions are implemented.

## Verification
Compare hashes of all pre-existing tracked files, validate new tool definitions against tool-contract-v1, exercise actual adapters with fake HTTP/OAuth transports, and run canonical workflow approval/execution through real Registry and GraphRunner. Check denial, timeout, uncertain writes, pagination, multi-sheet scope and file containment. Run the original backend/frontend regression suites and strict OpenSpec validation.

## Generalized Sheets follow-up
An absent or empty Sheets read/write configuration means no resource-specific operator ceiling, not a requirement to enter IDs. Read and discovery tools accept spreadsheet links selected per workflow; optional operator restrictions still narrow them. A new read-only discovery tool returns bounded real tab titles, headers and ranges. Fresh planning discovers only user-supplied links before model generation and supplies schema-only catalogs, never source row contents. New write binding still requires reviewed workflow-owned targets; inputs/results cannot enlarge those targets. URL and quoted-range normalization is applied to copies of execution/review data, preserving saved revision hashes and the original project modules.

## Generalized remaining connectors
Remove mandatory resource presets from connector availability and sample configuration. Calendar operations use any calendar permitted by Google, with optional operator ceilings; a new paginated discovery tool supplies IDs/names/timezones/access roles. Gmail profile discovery identifies the connected account, while workflow inputs and exact runtime gates own outgoing recipients; nonempty legacy recipient lists still narrow them. Search remains provider-backed with arbitrary bounded queries and optional runtime country/language/freshness filters. Planner context contains resource selection guidance and read-only Calendar discovery when calendar intent is explicit. Credentials, selected provider groups, budgets, artifact namespaces and action journals stay server-owned. No domain-specific procurement behavior or existing application code is changed.

## Independent workflow approvals
An extension-only RegistryService subclass adds a locked merge of exact unexpired workflow approval evidence. The extension RegistryAdapter uses this merge when reviewing another workflow so one review does not discard previously reviewed workflows’ grants. Canonical assignment, fingerprint and approver checks still validate the evidence. The inherited public update_approval_evidence keeps replacement semantics, including revocation with an empty snapshot; original Registry code is unchanged.
