# Whole-app acceptance and stability guide

Provide a source-grounded manual test sequence, expected outcomes, a result ledger,
and a current source-control inventory. Cover deployed screens, nested controls,
workflow/runtime/integration/data-query paths, failure/recovery and operational
stability. Clearly distinguish local drafts, server state, optional configured
providers and unavailable features. Do not claim that writing instructions runs
tests or establishes continuous availability. No service mutations, provider
writes, load tests or production restarts are part of preparing the guide.
