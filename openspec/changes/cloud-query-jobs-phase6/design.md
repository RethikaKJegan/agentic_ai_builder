# Design

Jobs use the serialized WorkflowStore write transaction boundary on SQLite and PostgreSQL. Submission binds owner/workspace, an immutable copy of the owned saved plan, its context fingerprint, expiry and idempotency key. No executable model text is introduced. Current server authority is resolved by worker identity, never copied from submission. Job reads, cancel and result retrieval require both tools.read and tools.assign. Queued/start/final validation checks plan expiry, current authority and graph/source freshness.

States: queued, validating, running, finalizing, succeeded, failed, cancel_requested, cancelled. Workers atomically claim with a random attempt token, 15-second lease and 1-second heartbeat. Shared claims allow at most four active jobs globally, one per owner/workspace. Admission bounds unfinished jobs at five per owner, twenty per workspace and one hundred globally, plus live result caps. Lease expiry permits one fresh retry, never reuse of partial states; fixed absolute deadline is not reset. Default job deadline is 180 seconds from submission, configurable between 45 and 300; statement, row, byte, precision and dimensional bounds remain. Plan expiry is also an execution bound. No automatic retry of ordinary source or correctness failures.

A request-local execution control reports real stages and fragment transfer counts, checks cancellation/authority/lease/deadline and tracks active PostgreSQL connections for driver cancellation. A monitor thread observes durable cancel/lease/authority changes while SQL is blocked. MongoDB uses existing operation timeouts and cancellation checks after bounded operations; no privileged global kill command. Final publication requires current authority/context and an unexpired matching claim in a serialized transaction; a previously committed cancellation wins. Results are validated, envelope-size bounded, encrypted with the persistent configured cipher and atomically stored in the job row. Stale workers cannot publish. Worker shutdown interrupts in-flight work and requeues at most once after connection cleanup; hard crashes recover after lease expiry.

GET status never decrypts row data. A separate owned result endpoint returns only complete unexpired results after current authority/context validation. Expiry logically removes ciphertext on access and periodic worker maintenance, keeps success state, and exposes result availability separately. Non-active metadata expires after 24 hours. Existing Fernet key configuration is reused and must be persistent/shared by API and worker. Idempotent repeated submission never reruns an existing job; changed payload under the same key conflicts.

The UI submits then polls, supports cancel, lists recent owned jobs for refresh recovery, restores server-held plan metadata and retrieves complete results. No row results or job authority are stored in browser storage; no guessed completion percentages. A submission key stays stable across network retries. Plain synchronous API remains for compatibility with its existing process-local concurrency bound; durable shared limits apply to background jobs.
