# Design

## Isolation
Use a new change and docs directory. Future business ontology definitions, namespace, API, persistence and versions must be isolated from the existing ontology foundation; shared source access may reuse existing authorized connectors.

## Chunk 1 evidence
Read only current local-workspace/local-builder connection rows from the application SQLite store in mode=ro. Reuse encrypted connector configuration in memory through CloudAdapters; do not copy credentials or instantiate application services. Require exactly one connected MongoDB source per explicitly allowlisted Simpson connection ID. Recheck connection secret/document fingerprints after the diagnostic; report drift.

Profile at most 100 initial records per collection using server-side $type aggregation. Retain only per-field missing/null/type counts. A model declaration is not proof of stored values, sampled presence is not population completeness, and missing fields in the bounded sample are not schema absence. Probe selected same-database direct references with server-side lookup and aggregate cardinality counts; do not treat serial-only associations as resolved engine identity. Query limits are three seconds per operation and the connector deadline applies independently per connection. Failed checks remain unavailable.

## Rule authority
The blueprint describes intended capability; the supplied backend describes implemented behavior; live probes describe sampled source state. Preserve each basis separately. Warranty thresholds are hardcoded in the supplied backend; its date basis is evaluation time and its comparisons are inclusive calendar-month differences. No complete coverage/exclusion policy has been identified. Do not infer policy correctness from an existing underWarranty boolean.

## Chunk 2 foundation
Use additive `business_ontology_workspaces`, `business_ontology_versions` and `business_ontology_events` tables scoped by trusted workspace and owner. Explicit initialization binds two distinct owned connected MongoDB sources to service and quality roles. The saved foundation snapshot contains five layers, twelve module descriptions and zero generated concepts; it is not an ontology release or graph. Initialization is idempotent for identical bindings and rejects attempts to silently replace an existing workspace. Read operations never initialize it.

Expose separate `/business-ontology/v1` read, `/initialize` POST, and immutable `/versions/{version_id}` lookup through existing session/origin transport. Require tools.read + workspace:read for reads and tools.assign + workspace:write for initialization. Validate exact payload keys; reject foreign/disconnected sources. Recheck saved source availability and metadata revision on reads. This chunk performs no company queries or model calls.

The Business Ontology tab loads backend state, lets managers bind service/quality connections and initialize the foundation, and navigates actual persisted layer/module descriptions. Show zero concepts and explain that generation follows in the next chunk. No simulated generation, graph, SME review, release, or publication controls.

## Chunk 3 extraction
Add owner-scoped evidence documents and durable module-generation jobs. The UI can import a sanitized reference bundle prepared from the supplied blueprint/backend only when the original recorded service/quality connection IDs are owned and bound; other scopes may supply their own documents. Input documents are untrusted evidence, not instructions. Never load .env or arbitrary archive files into prompts. Current source context uses only allowlisted metadata field names/types from both bound saved snapshots, not company records or credentials.

Each explicit request generates one module with the existing configured OpenAI model and Responses strict JSON Schema. One bounded call, no automatic provider retry, no fallback model, no tools or source writes. Store source hashes, exact evidence quotations, unknowns, model and prompt/schema versions and token usage. Validate shape, IDs, layers, module boundaries, citations and relationship/parent references before atomically saving a new immutable draft version. This is structural extraction validation, not the later OWL/SHACL compiler or business-policy verification. Rules remain non-executable candidates.

Jobs use scoped idempotency keys, revision checks, database claims and deadlines. Recheck authority, source metadata/generation and base revision before applying results. Expired uncertain jobs fail without automatic replay. Repeated module generation replaces only that module and cannot remove concepts referenced by retained modules. Cancellation discards late results; it cannot undo model usage. Register the worker with both local and existing supervised API/worker lifecycles.

## Chunk 4 compiler and automated validation

Compile an explicitly selected immutable draft version without a model call, company query or live source dependency. Store an additive owner/workspace-scoped compilation alongside the unchanged draft. A compiler version and canonical input SHA-256 identify the result; repeated requests for the same snapshot are idempotent. Historical versions compile independently. Foundation-only snapshots are rejected.

Use RDFLib and pySHACL with no remote imports, custom SPARQL, JavaScript, SHACL rules or OWL inference. Mint stable IRIs from the existing owned namespace and escaped internal IDs, never interpret model strings as external IRIs or syntax. Concepts become OWL classes and parent links become rdfs:subClassOf. Each relationship ID becomes its own OWL object property with the declared domain/range; predicate text remains an annotation. Each concept attribute becomes a concept-scoped datatype property, except reference attributes which become object properties with an IRI constraint and unspecified target class. Datatypes map explicitly to XSD; enumeration stays a string with an unresolved-values warning. Do not infer cardinality beyond declared required/minCount=1, relationship requiredness, inverses, equivalence or business thresholds. Rule candidates remain annotated non-executable resources.

Export ontology Turtle and RDF/XML, instance SHACL Turtle, definition-validation SHACL Turtle and a JSON report in a version-bound bundle. Preserve module/layer, draft status, source hashes/quotations, extraction metadata and unknowns. Exporting a structurally conforming draft does not publish it or approve policy. Generated instance shapes are meta-SHACL checked; a separate SHACL graph checks generated class/property/rule/evidence definitions. Revalidate snapshot structure, references, hierarchy and citations before compilation; surface safe issues and mapping limitations. Report instance validation as not_run and business_policy_verified=false. No all-clear based on an empty instance graph.

Expose scoped GET/POST `/versions/{version_id}/compilation`: GET never compiles, POST accepts only `{}` and manager/write authority. Add a selected-version compilation panel with explicit action, actual persisted report, errors/retry, historical isolation and browser downloads. Viewer access permits read/download but not compilation. Existing Ontology and Semantic Intelligence remain independent; no SME gate, execution, graph ingestion, publication or deployment.

## Chunk 5 rule catalogue and competency queries

Add a read-only version-bound rule catalogue built from the validated immutable snapshot: preserve each candidate's source basis, exact quotations/hashes/kinds, conditions/outcome, input concepts and declared attributes, unknowns and module questions. Draft/policy-source presence never implies business approval, policy completeness, data availability or executable rules. Foundation versions return an honest empty catalogue.

Provide six fixed definition-level competency SELECT queries over the already persisted, passed compilation: rule inputs, rule evidence, policy-source candidates, implementation candidates, concept relationships and unresolved definition information. Accept only an allowlisted query ID, optional existing rule/concept focus, bounded limit and offset; use RDFLib variable bindings, never caller-authored SPARQL/IRIs or remote endpoints. Both viewer and manager reads are allowed. Verify compilation version, canonical snapshot input hash, report conformance and ontology artifact hash before parsing local generated Turtle. No auto-compilation, mutation, model call, company query, inference or warranty evaluation. Return stable rows, columns, explicit empty versus prerequisite-unavailable states, pagination and version/compiler/query/graph provenance. No hidden empty-result fallback on failures.

Include the 22 supplied blueprint business questions as a separate reference catalogue with explicit missing instance-mapping/policy/temporal/identity/confirmed-failure/exposure prerequisites. They remain unavailable until the later mapped graph and policies exist; structural concept-name matches do not establish readiness. Preserve supplied blueprint hash/section provenance, not its excluded SME-review instructions. This chunk implements schema-level query behavior and fixtures; company-instance competency query templates are later mapping work.

In the selected-version definitions view, add a searchable module/basis-filtered rule catalogue with rule details/evidence and a competency-question panel. Run queries only on explicit action, provide bounded result pages and evidence links, and clear stale results on version, query, focus or catalogue refresh changes. Refresh compilation readiness after a successful explicit compile without automatically rerunning a query. Managers and viewers can use read-only queries. Existing Ontology/Semantic Intelligence, shared contracts and operational approvals remain unchanged; no SME gate or deployment.

## Chunk 6 bounded source graph and engine path

Use both bound owned MongoDB sources through existing encrypted connection ownership and CloudAdapters. Expose a code-owned mapping catalogue for the 21 reviewed collections; safe scalar projections derive only from the reviewed field inventory and current metadata. Explicit managers choose generated concept IDs and attribute-to-field bindings for available collections, with exact request validation and current-plan hash. Do not infer bindings from labels. Require a passing integrity-checked compilation for that definition version. Reads never start source queries; explicit build/save does. Viewers inspect saved snapshots only.

An exact bounded engine-serial search fetches invoice/ticket/manual-claim/SAP-claim/failed-engine-analysis records, then fixed same-source ticket child references, OEM/account references, and explicitly qualified engineering/CAPA candidates where usable scope fields exist. Limit each collection to 20 records plus one truncation probe, total deadline 25 seconds, response/store 2 MB, no automatic retry or background unbounded scan. Report collection unavailable/not-in-path/missing metadata separately from zero matches and truncation. Query both databases even when one returns no match. No company writes or model transfers. Secrets remain in memory and projected records are scalar allowlists only; reject sensitive returned payloads.

Build record identities from source/collection/native BSON-typed key, never engine serial. Preserve independent read times and value states. Direct same-database foreign-key edges require exact type/value match and one observed target; dangling/ambiguous references remain unresolved, including the accepted replacement gaps. Serial matches across records/databases are candidate edges, never sameAs/physical-engine identity. Engineering/CAPA scope matches are candidates, not incorporation or confirmed recurrence. A bounded sample is not a population or historical snapshot.

Save an additive owner/workspace/version-scoped immutable graph snapshot with request-key idempotency, source metadata/generation/credential fingerprints and current authority rechecked before/after I/O and before commit. Generate local RDF with source-record identities, manually bound classes/attributes, explicit source/candidate edges and provenance; no semantic merge. Validate mapped instances against saved SHACL locally and expose conformance/violations, invalid value conversions and unmapped fields without claiming mapping correctness or policy verification. No eligibility rule execution. Stage coverage shows engine/complaint/inspection/replacement/quality/effectivity/CAPA record presence and monitoring unavailable pending incorporation, confirmed comparable failures and exposure denominators.

UI under the selected version: metadata-only mapping controls, concept/attribute selection, exact serial input, explicit build/save, snapshot history, stage coverage, record/edge/provenance inspection, unresolved/truncation/collection outcomes and RDF/report downloads. Existing Ontology, Semantic Intelligence, source configs and shared execution contracts unchanged. Live diagnostic, if run, must use a separate read-only application-store resolver and private artifact directory without starting services or initializing the live business workspace. No SME gate, deployment or automatic new OpenAI call.
