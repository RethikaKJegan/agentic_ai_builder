# Design

On a Google HTTP 400 for a syntactically valid named A1 range, the reader checks worksheet metadata. It retries against the sole actual tab only when the requested title is absent and exactly one tab exists. Multiple tabs or an existing requested title fail with SHEETS_RANGE_INVALID. This recovers document-title/tab-title confusion without guessing among multiple data sources. First-read baseline and header/identity validation still apply.

Event paths support dictionary attributes and literal dictionary/list subscripts, with no calls or computed expressions. Publication checks the same parser used for ingestion. Existing failed polls keep their checkpoints so newly added rows can dispatch after recovery. Monitoring sums workflow counters once (agent counters are the same reservations), exposes scoped source/checkpoint health, reviewed agent guardrails and safe runtime audit references. Governance presents this server data separately from local draft policy controls.

Fresh planner proposals are untrusted capability requirements. After checking the raw proposal for secrets, the planner clears agent allowed_tool_ids and removes tool configuration_reference before validation and caching. This prevents model-proposed authority from blocking UI draft saving. Direct client saves continue to reject executable assignments; only Registry review can issue them.

An explicit BUILDER_EMAIL_DIRECT_SEND=1 operator setting enables only allowlisted smtp_send_email direct writes. Registry metadata marks that configured tool approval_required=false; the SMTP connector and graph runner each require their server-owned direct-send setting as well as an exact authorized grant. Default approval behavior is retained. The workflow must explicitly omit its approval node and sender approval requirements to take the direct path; publication remains a reviewed revision. A wrong upstream service yields a canonical API_WRONG_SERVICE proxy response. Operator commands use port 8002 to avoid the other service observed on 8000.

Published Sheets resource references may be either spreadsheet IDs or Google Sheets URLs. The provider boundary extracts the ID from an HTTPS docs.google.com/spreadsheets/d/ URL, preserving immutable workflow/release documents. Invalid or foreign URLs fail before any provider request. Event IDs and mapped spreadsheet_id values use the extracted ID consistently.

Checkpoint persistence uses a workspace-scoped UPDATE followed by INSERT when absent, within the existing write transaction. This supports both legacy binding_id-primary-key tables and current workspace/binding_id composite keys without dropping tables, changing authority or resetting cursors.

The launcher supplies provider credentials through opaque server-owned references, registers enabled read/email tools and attaches a bounded CrewExecutor and workers before startup. No workflow is created or published by the launcher. Existing UI generation, validation, publication and release activation remain authoritative.

Sheets row.created bindings declare an identity_field and required_fields in poll_input. The adapter retains observed stable identifiers across sorting, deletion and polling; partial new rows remain pending until complete. First polling establishes a current-only baseline. Duplicate identities or invalid headers fail closed. Other polling modes preserve existing behavior. Lifecycle checkpoints advance after successful ingestion of an entire batch, including filtered and duplicate receipts.

Planner guidance defines metadata.trigger_templates and explicit node input mappings. Conditions and email destinations/content belong to the workflow. Registry preserves authored output mappings and validates required tool fields against them. Model requests have exact configured model, conservative token reservation, explicit tokenizer configuration for models absent from installed tiktoken, no SDK retries and no response storage. SMTP retains reviewed recipient allowlists and per-action approval.

Provider checks read Sheets and authenticate Gmail without sending email. Bounded model smoke calls use synthetic inputs. End-to-end tests exercise two CrewAI agents, branch skipping, approval/rejection, stable dedup and restart using controlled providers. Live delivery is verified only when a real published workflow receives a new row and the user approves its email.

Generation safety follow-up: live planning must apply the Registry secret-field scan to raw model proposals before returning them. A rejected proposal may use the existing single bounded correction with code-only feedback; no flagged values are sent back, cached, saved or returned. Repeated unsafe output reports a provider-output failure rather than blaming the user's prompt. Incoming request secret checks stay unchanged.

Creation retry follow-up: Overview's planner returns a stable workflow identity for the same objective, while its save always assumes version 1/base 0. If that identity already exists, the create flow must fetch and open the current saved workflow on REVISION_CONFLICT and explicitly notify the user. It must not overwrite the saved graph, increment a revision blindly, or alter release state. Other save errors remain visible.

Complaint budget follow-up: CrewExecutor reserves each model node's full agent cost ceiling, and an omitted workflow cost ceiling is zero. Live planning must reject proposals whose total model-node cost reservations exceed the workflow cost ceiling and provide bounded correction feedback. This must not increase a published budget automatically. Repair existing affected workflows through a new draft revision for review/publication; preserve blocked runs and current release snapshots.
