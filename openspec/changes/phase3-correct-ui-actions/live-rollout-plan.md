# Phase 3 controlled rollout

Authorization: the user requested Phase 3 implementation after Phase 2 was implemented and loaded. This rollout loads only the tested changes into the existing three Builder systemd services. It does not change Google credentials, public authentication, SQLite/PostgreSQL selection, nginx, firewall, DNS or unrelated applications. No external message/model/resource mutation is submitted by verification.

1. Finish frontend unit/types/lint/build and real isolated desktop/mobile browser checks, relevant/full backend/connector regressions, canonical contracts, strict OpenSpec and inventory drift checks. Keep failures visible until corrected and rerun. Final counts are recorded in verification.md.
2. Preserve earliest Phase 3 existing-file originals privately in `.local/phase3-rollout/phase2-source/`; verify source hashes. New modules do not require deletion for rollback because the old main/live provider modules will not import them. Preserve the original tested frontend `.next` build. Do not use git reset; Phase 1/2 and earlier user changes are uncommitted.
3. Stage a complete copy of `.local/phase3-verification/frontend/.next` as `.local/phase3-rollout/tested-next` before stopping services. Never build inside the active frontend build directory. Match the staged and tested BUILD_ID.
4. Gracefully stop only `agentic-builder-worker.service` first, then `agentic-builder-backend.service`. The worker drain is bounded by the existing 240-second service limit. Record any interrupted operation for reconciliation; never replay uncertain external effects. Confirm old PIDs have exited. Run the private SQLite online-backup script for the main database and actual procurement/effect/sheet-resource files. Keep source files and private .env untouched.
5. Start the API-only backend and verify local session/protected read; compare all preexisting table row counts against the stopped-state backup before starting workers. Additive workflow submission uses existing revisions/mutations tables; no schema cutover occurs.
6. Stop `agentic-builder-frontend.service`, move its `.next` directory to `.local/phase3-rollout/phase2-next`, rename the staged `tested-next` into `.next`, and start the frontend. Preserve the old build intact. API upstream remains loopback port 8002; frontend remains loopback 3001.
7. Start the existing separate worker service. Confirm exactly one durable owner, stable API/worker/frontend, authenticated local read/proxy success, public development API/session rejection, HTTPS HTML/assets, relative browser API URLs, correlation IDs and no-store responses. Read-only integration configuration checks may be observed; do not click live SMTP verification or mutate settings/workflows in production smoke.
8. If startup/read checks fail, stop the worker/backend/frontend, verify no source changed after checkpoint, restore only the earliest Phase 3 existing-code originals, restore the previous Next build and restart the prior API/worker/frontend services. Keep all business database contents; do not restore an old snapshot over new post-rollout activity. Do not remove Phase 2 worker role configuration. Record the failure and rollback before retrying.

Public authenticated production success remains deferred with Google Workspace login. Existing configured background workers may resume normal provider activity after restart; that is distinct from smoke actions. No claim of zero background external activity is made.
