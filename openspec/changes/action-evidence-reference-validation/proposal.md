# Validate and correct action evidence references before compilation

## Why
Hosted generation rejects content references after the existing bounded correction boundary. The request logs do not retain the offending reference; no exact rejected proposal is claimed. Known action citations also do not materialize dependency edges as data bindings do.

## What Changes
For automatic-input plans, materialize references to existing distinct actions as explicit dependencies, preserving pinned evidence identities. Validate evidence references inside the guarded planning boundary and provide exact invalid/allowed IDs for one bounded correction. Keep unknown references, cycles, conditional dependencies and explicit/manual invalid plans rejected. Preserve query handoffs, account selection and exact-payload approvals.

## Impact
Backend-only; no shared contract or database migration. Controlled model/provider tests, copied-store startup and existing verified backup/rollback deployment process. No paid model calls or real provider effects.
