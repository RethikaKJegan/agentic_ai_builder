# Account and plain-language workflow goals — 5 November 2026

The main investigation prompt and connected investigation builder now accept a Google account and a plain-language goal. The planner discovers registered capabilities; the server supplies stable internal workflow/action identifiers and connector-declared defaults. Generated content supplies titles, report tabs and email content from actual completed dependencies. Explicit email addresses can come from the goal; “email me” resolves to the selected owned account. Missing business information produces a labelled question, rather than a technical JSON form.

The UI removes the manual connected-action selector, project/creation keys, tabs JSON, generic user-values JSON and upfront recipient form. Review plan saves and validates; workflow approval, execution and exact external-payload approval remain explicit. A prompt requesting approval before creation still pauses for that approval. Selecting an account does not authorize unrelated operations or destinations.

Capability discovery has no fixed connector-count cap or provider allowlist. Additional connectors require registered schemas, an installed adapter and credentials/permissions. Existing action-count, time and execution budgets remain. Google operations require the selected owned account and fail on revocation rather than falling back to another account. Generic connectors use their own configured credentials. This does not add a new search provider; already registered search/page tools can contribute real returned content to generated reports through declared dependencies.

Existing saved workflows retain their architecture and contracts. Goal-mode composition metadata enables multi-dependency content inputs; existing advanced compositions keep their original input shape. Pinned client-package regeneration retains its package revision. No shared contract schema or database migration was introduced.
