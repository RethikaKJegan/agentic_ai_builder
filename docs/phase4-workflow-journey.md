# Phase 4 workflow journey

Phase 4 implements correction-plan sections 12–16 on the existing React Flow/domain editor. Generation now offers an explicit automatic-source or manual-input choice, persists only a draft and displays a structured proposal before the user chooses Review and edit workflow. It shows actual goal, inputs, trigger templates, outputs, steps/branches, agent responsibilities, tools, approval gates and configuration review requirements. A repeated identity opens its existing saved revision and never overwrites a dirty browser draft. Failures preserve the prompt and expose safe field/error references and explicit retry. Regeneration of an existing review requires an explicit choice.

The editor's visible lifecycle progress and expanded 14-stage guide distinguish current draft revision, latest published revision and exact active release revision, including prerequisites and next actions. Existing explicit Save/Validate/Submit/Approve/Publish/Activate controls retain server permission, Registry, idempotency and concurrency boundaries. A new read-only authenticated GET `/workflows/{id}/release-state` returns workspace-scoped release ID/version/state and binding count through the existing canonical envelope. It does not change the existing overview/shared schemas. Trigger-binding count is not a provider health or successful-event claim.

Design edits only the current working graph; it never overlays run status. It shows start/end and node kinds, directed branch labels, graph diagnostics, dependency-ordered mobile/accessible outlines, keyboard connection/remove controls and existing React Flow layout/fit/zoom/minimap. Drag undo preserves pre-drag positions; undo/redo remain local edits and are disabled outside Design. Supported node layout positions persist through existing canonical saving. Local diagnostics do not replace authoritative server validation.

Agent hierarchy shows canonical master agents and delegated specialist templates, including templates without graph nodes, parent/child responsibility, reviewed tool access and configuration state. Supported dynamic delegation is distinguished from presentation-only links. A relationship alone does not create executable dependencies. Design contains actual execution topology.

Execution loads the selected persisted run and its exact workflow revision into a separate read-only view. The editable draft remains mounted and is not replaced in the store. Historical topology uses a separate readable display layout; saved design positions remain unchanged. Failure to load the exact revision displays an error rather than the current graph. Recorded agent configuration is supplied to historical node rendering; current agent settings cannot leak into historical cards. Run ID/version, node evidence, safe recorded input/output/failures, retry history and timing are shown only where recorded. Missing events mean unknown status, not completed/not-run. Selected recorded paths are highlighted.

Runtime event reads add `details.recorded_sequence` from the existing database sequence without rewriting stored evidence. Client reconciliation deduplicates identity, rejects conflicting identities/sequences and orders by recorded sequence. Legacy arrays retain server order rather than being reordered by timestamps. No shared v1 event schema or database migration is required. Terminal selected-run polling stops; Refresh trace supports explicit rereading. Broader pagination/stream policies remain Phase 6 scope.

Safe runtime simulation remains explicitly unavailable because no supported side-effect-free simulation adapter is installed. Validation is not labeled simulation. Google Workspace production login remains deferred by the user, so public development sessions/API stay forbidden. SQLite remains the live database; isolated PostgreSQL verification is not a cutover. See the Phase 4 verification report, exact existing-code patches and action audit supplement for evidence.
